Herdr works without a config file. Add one when you want custom keys, themes, sidebar layouts, notifications, or advanced behavior.

Looking for any setting or keybinding? Search the [Config reference](/docs/config-reference/) for every key, type, default, and allowed value. This page focuses on setup, common recipes, and configuration structures that need more explanation than a reference row.

## Config file

Herdr reads config from:

```text
Linux and macOS: ~/.config/herdr/config.toml
Windows:          %APPDATA%\herdr\config.toml
```

Run `herdr --help` to see the resolved config path for your system.

Print the full default config:

```bash
herdr --default-config
```

Save it as your config if you want a complete starting point:

```bash
herdr --default-config > ~/.config/herdr/config.toml
```

If a config value is invalid, Herdr falls back to a safe default and shows a startup warning.

Herdr shows first-run setup when `onboarding` is missing or true. Continuing from onboarding writes `onboarding = false` and opens settings on the integrations tab. Set it when you want to skip that flow after setup.

```toml
onboarding = false
```

## Reload config

Reload a running server after editing `config.toml`:

```bash
herdr server reload-config
```

You can also open the global menu in Herdr and choose `reload config`.

Reload applies most UI settings without restarting panes. Startup-only settings still need a restart.

## Terminal defaults

Set the executable Herdr uses for newly created interactive panes:

```toml
[terminal]
default_shell = "nu"
```

When unset or empty, Herdr uses `$SHELL`, then `/bin/sh` on Unix and PowerShell on Windows. This is an executable name or path, not a shell command line. Existing panes keep their current shell until they are recreated. Custom command keybinding strings run through `/bin/sh -c` for pane commands and `/bin/sh -lc` for detached commands on Unix; on Windows they run through `cmd.exe /d /c`.

Set how Herdr starts newly created interactive pane shells:

```toml
[terminal]
shell_mode = "auto"
```

`shell_mode = "auto"` starts login shells on macOS so login-only PATH setup such as `/usr/libexec/path_helper` and Homebrew shell initialization runs in new panes. On other platforms, it keeps the existing non-login shell behavior. Use `"login"` to force login-shell startup, or `"non_login"` to opt out. Command panes, detached custom command keybindings, and explicit argv launches keep their existing command execution paths.

Set the working directory policy for new panes, tabs, and workspaces:

```toml
[terminal]
new_cwd = "follow"
```

`new_cwd = "follow"` keeps the default behavior and inherits the source pane or workspace. When there is no source workspace, Herdr starts in `$HOME`. Use `"home"` to always start in `$HOME`, `"current"` to use Herdr's process directory, or a fixed path such as `"~/Projects"`. Explicit `--cwd` values from the CLI or socket API still take precedence.

## Worktrees

Set the root directory Herdr uses for Git worktree checkouts created from the sidebar:

```toml
[worktrees]
directory = "~/.herdr/worktrees"
```

Herdr creates checkouts under `<directory>/<repo>/<branch-slug>`. For sibling-style checkouts, set this to a directory such as `~/Projects/herdr-worktrees`. Relative values are resolved to an absolute path when the app applies the config.

Worktree actions are available from Git workspace rows. `New worktree` creates a checkout, checks out an existing local branch when the entered branch already exists, otherwise creates the branch, opens it as a new Herdr workspace, and groups it under the source workspace. `Open worktree...` lists existing Git worktree checkouts for that repo; choosing an already-open checkout focuses it, and choosing a closed checkout opens it in the same group.

Grouped worktrees still behave like normal Herdr workspaces: they can be focused, renamed, closed, and contain their own tabs and panes. The parent row is the original workspace. Closing the parent row closes the whole Herdr group, but it does not delete checkout folders or branches.

Deleting a worktree checkout is explicit. Use `Delete worktree checkout...` on a grouped child workspace to run `git worktree remove`. Herdr first asks Git to remove safely. If Git refuses because the checkout has modified or untracked files, Herdr asks again before running the forced remove. Branches are not deleted.

## Splitting a repository into several spaces

By default every checkout of a repository shares one sidebar space, headed by the repository's main checkout. That is the right grouping when a repository is one project. When a single repository holds several independent modules, `[[spaces.split]]` rules regroup it by module instead:

```toml
[[spaces.split]]
repo = "~/panel"
match = ["feat/billing-*", "fix/billing-*", "*invoice*"]
key = "panel:billing"
label = "Billing"

[[spaces.split]]
repo = "~/panel"
match = ["*reporting*"]
key = "panel:reporting"
label = "Reporting"
```

`repo` is the repository root, absolute or `~`-rooted. `match` globs are tested against the checkout's branch first, then its directory name, so a detached checkout is still claimable; `*` is the only wildcard and a pattern without one must equal the whole value. `key` is the space the matched checkouts group under, and `label` is the group header — set it, because the header names the module rather than whichever checkout leads it.

The first matching rule wins, in config order. Checkouts no rule claims keep the repository space, so adding a rule never disturbs the checkouts it does not mention, and an empty list behaves exactly as if the section were absent. A space with a single member renders as a plain row, the same threshold repository groups use.

Rules are resolved when the sidebar renders, not stored in the session, so `herdr server reload-config` regroups every open workspace immediately. An unusable rule — no `repo`, a relative `repo`, no `key`, no pattern — is reported and skipped rather than failing the config load, and two rules sharing a `key` are reported because they would silently merge two modules into one space.

A rule may also carry an `icon`, a glyph drawn before the group header's label.

## Gathering repositories and spaces under a project

One level above the split rules, `[[spaces.project]]` entries gather whole repositories and individual spaces under a single top-level header, so several repositories serving one product read as one project:

```toml
[[spaces.project]]
name = "herdr"
key = "project:herdr"
icon = "🚀"
repos = ["~/projects/herdr", "~/projects/herdr-web"]
spaces = []
```

`repos` claims every space of those repositories — the repository space itself and any spaces split out of it. `spaces` claims individual space keys regardless of repository; `herdr space promote` writes entries of that shape. `key` stores the project's collapse state and must be unique; `name` falls back to the key when blank, and `icon` falls back to `spaces.icons.project`.

Projects follow the same rules as split rules: the first matching project wins in config order, resolution happens at render time so `herdr server reload-config` regroups immediately, an unusable entry — no `key`, a relative repo, no usable member — is reported and skipped, and a duplicate `key` is reported because two projects would share one collapse state. An empty project list leaves the sidebar exactly as it was.

### Deeper trees with `[[spaces.node]]`

When two levels are not enough, `[[spaces.node]]` containers give the tree its
N-level shape. A node is a named header that hangs under another node by
`parent`; a split rule may carry a `parent` of its own to hang its bucket under
a node, and a project may too — a project *is* a node, just a parentless one by
default:

```toml
[[spaces.node]]
key = "node:ui"
name = "UI Layer"
icon = "🎨"
parent = "project:herdr"

[[spaces.split]]
repo = "~/projects/herdr"
match = ["feat/sidebar-*"]
key = "herdr:sidebar"
label = "Sidebar"
parent = "node:ui"
```

`key` is the node's identity and its collapse state; `name` falls back to the
key and `icon` to `spaces.icons.project`. An absent table changes nothing.
Tree-shape problems degrade loudly instead of failing the load: a `parent`
nobody defines keeps that node at top level, a parent cycle drops every member
of the cycle to top level, and a chain deeper than eight is reported while the
sidebar's indentation stops growing at six. A parented bucket with a single
member draws no header of its own — the checkout hangs directly under the
node, which is what "move this branch under X" should look like.

### Renaming a header with `[[spaces.display]]`

Every module header — a `[[spaces.node]]` container, a `[[spaces.split]]`
bucket, or a `[[spaces.project]]` umbrella — can be renamed from its own
right-click menu. The new name is written as a `[[spaces.display]]` entry keyed
by the rule's own key:

```toml
[[spaces.display]]
key = "herdr-web:tabs"
name = "Sekmeler"
```

A display entry is a name and nothing else. It carries no `repo`, no `match`
and no `parent`, and it is applied *after* the rules above have resolved
everything, so renaming a bucket cannot move the branches it claims, cannot
reorder first-match, and cannot lift a module out of its place in the tree or
take away the directory it stands in. That is what lets the verb be offered on
hand-written modules at all: rewriting the rule would work only for entries
Herdr itself wrote, because a second rule carrying an existing key is either
dropped as a duplicate or loses at first-match to the one it was meant to
rename.

When more than one entry names the same key the last one wins — the managed
overlay is merged after your own file, so "last" means the most recent
decision. A blank `name` is ignored. Deleting a module deletes its display
entry with it.

## Row icons in the Spaces tree

`[spaces.icons]` sets the default glyph per row kind — project headers, workspace (branch) rows, and chat drawer rows. Every field has a working default, so the table is only written to change taste. An empty string disables that glyph.

```toml
[spaces.icons]
project = "📁"
branch = ""
chat = "💬"
```

## Remote attach

Remote attach manages its SSH connection with a temporary keepalive and connection-reuse fallback by default.

```toml
[remote]
manage_ssh_config = true
```

When enabled, `herdr --remote` writes a private temporary SSH config that includes your `~/.ssh/config` and `/etc/ssh/ssh_config` first, then adds fallback `ServerAliveInterval` and `ServerAliveCountMax` values. Your own keepalive settings win. Herdr also uses a private per-attach OpenSSH control socket to reuse the first authenticated connection. Set `manage_ssh_config = false` to run remote attach through plain `ssh` without Herdr's generated config or control socket.

## Keybindings

For a guided introduction to the prefix and a vetted prefix-free setup, see [Keyboard](/docs/keyboard/).

Herdr has a prefix mode similar to tmux. The default prefix is `ctrl+b`. Keybinding strings are explicit: `prefix+n` means press the configured prefix and then `n`; `ctrl+alt+n` is a direct terminal-mode shortcut.

A small keybinding override looks like this:

```toml
[keys]
prefix = "ctrl+b"
goto = "prefix+g"
new_tab = "prefix+c"
next_tab = "prefix+n"
previous_tab = "prefix+p"
focus_pane_left = "prefix+h"
navigate_workspace_down = "j"
navigate_pane_down = "ctrl+j"
split_horizontal = "prefix+minus"
```

The default keymap is prefix-first so Herdr does not steal input from shells, editors, tmux, or terminal apps. Search `keys.` in the [Config reference](/docs/config-reference/) to see every action and default binding. The in-app help panel at `prefix+?` shows the active bindings.

A binding may also be an array when one action needs multiple shortcuts:

```toml
[keys]
next_tab = ["prefix+n", "ctrl+alt+]"]
```

Optional actions are unset by default. Bind them with `prefix+` for prefix-mode behavior, or use an explicit modified chord when you intentionally want a direct shortcut.

Key strings accept plain keys, modifier combinations such as `ctrl+a`, `shift+n`, `alt+1`, `cmd+k`, and special keys such as `enter`, `tab`, `esc`, `left`, `right`, `up`, and `down`. Named punctuation such as `minus`, `comma`, `ampersand`, `plus`, and `backtick` is also accepted. Plain direct printable keys such as `n` are unsafe because they intercept typing; use `prefix+n` unless you intentionally want a direct binding. The `navigate_workspace_*` and `navigate_pane_*` fields are navigate-mode-only and may use plain keys such as `j` or `k`; they must not use `prefix+`, `esc`, `enter`, `tab`, `shift+tab`, `left`, `right`, or unmodified `1` through `9`. Left and right arrows are permanent aliases for pane-left and pane-right navigation. These navigate-mode shortcuts are independent from general action bindings such as `focus_pane_down = "prefix+j"`; when both use the same key, the navigate-mode shortcut wins while navigate mode is open. Alt, Cmd/Super, and punctuation with modifiers depend on your terminal and tmux settings.

If you have old custom keybindings and want the new defaults, run `herdr config reset-keys`. Herdr backs up `config.toml`, removes `[keys]` and `[[keys.command]]`, and uses built-in v2 defaults after restart or `herdr server reload-config`.

## Indexed jumps

Indexed keybindings use `1..9` in normal keybinding fields:

```toml
[keys]
switch_tab = "prefix+1..9"
switch_workspace = "prefix+shift+1..9"
focus_agent = "prefix+alt+1..9"
```

The legacy `[keys.indexed]` table is still parsed for compatibility, but new configs should prefer the explicit action fields.

## Custom command keybindings

Custom commands use the same keybinding syntax.

```toml
[[keys.command]]
key = "prefix+alt+g"
type = "popup"
command = "lazygit"
description = "run lazygit"
width = "80%"
height = "80%"
```

`type = "popup"` opens a session-modal popup without changing the tab layout.
The popup receives all terminal input, including Escape, until its command
exits. `width` and `height` are optional; omit them for the default half-size
popup, use numbers for terminal cells, or use strings like `"80%"` for a
percentage of the terminal area. Dimensions include the popup border, and
values smaller than the popup minimum are clamped. Popup commands do not receive
`HERDR_PANE_ID`; use `HERDR_ACTIVE_PANE_ID` for the underlying tiled pane.

On Unix and macOS, a popup command can also provide an ad-hoc terminal without
adding a split or tab:

```toml
[[keys.command]]
key = "prefix+t"
type = "popup"
command = "exec \"${SHELL:-sh}\""
description = "open scratch terminal"
width = "80%"
height = "80%"
```

On Windows, use a shell command such as `command = "powershell.exe -NoLogo"`
instead. Exit the shell to close the popup and restore the tiled terminal view.

`type = "pane"` opens a temporary zoomed pane and closes it when the command exits.

`type = "shell"` runs detached in the background.

`type = "plugin_action"` invokes an installed plugin action id. Use the
qualified id when action ids are not globally unique:

```toml
[[keys.command]]
key = "prefix+l"
type = "plugin_action"
command = "example.layout.apply"
description = "apply layout"
```

An optional `description` can be provided. When specified, this description is displayed in the keybind help panel (opened with `prefix+?`) in place of the default `'custom command'` label.

Custom commands receive `HERDR_SOCKET_PATH`, `HERDR_BIN_PATH`, `HERDR_ACTIVE_WORKSPACE_ID`, `HERDR_ACTIVE_TAB_ID`, `HERDR_ACTIVE_PANE_ID`, and `HERDR_ACTIVE_PANE_CWD` when those values are available. Shell commands run from the focused pane's working directory when Herdr can detect it.

On Windows, custom command strings use `cmd.exe /d /c`, so environment variables use `%HERDR_BIN_PATH%` syntax. To run PowerShell syntax, invoke it explicitly, for example `powershell.exe -NoProfile -Command "..."`.

## Theme

Choose a built-in theme:

```toml
[theme]
name = "catppuccin"
```

Search `theme.name` in the [Config reference](/docs/config-reference/) for every built-in theme. Use `terminal` when you want Herdr UI colors to follow your host terminal's ANSI palette.

To let Herdr switch its own UI theme when the host terminal reports a light/dark appearance change, enable theme auto-switching:

```toml
[theme]
name = "catppuccin"
auto_switch = true
light_name = "catppuccin-latte"
dark_name = "catppuccin"
```

`auto_switch` defaults to `false`, so existing theme configs keep manual behavior. If `light_name` or `dark_name` is omitted, Herdr uses the matching built-in sibling for the configured `name` when one exists, such as `tokyo-night`/`tokyo-night-day` or `gruvbox`/`gruvbox-light`. Manual theme selection in Settings disables `auto_switch`.

You can override individual colors:

```toml
[theme.custom]
panel_bg = "reset"
accent = "#a6e3a1"
green = "#a6e3a1"
blue = "#89b4fa"
red = "#f38ba8"
yellow = "#f9e2af"
```

Color values accept hex, named colors, `rgb(r,g,b)`, or reset aliases like `reset`, `default`, `none`, and `transparent`.

## UI and sidebar

The sidebar is the main Herdr dashboard. Search `ui.` in the [Config reference](/docs/config-reference/) for sizing, collapsed mode, Agent panel ordering, mouse behavior, pane borders, and other presentation settings.

### Sidebar row layouts

The expanded desktop sidebar renders each inner array in `rows` as one line. These are the complete default layouts:

```toml
[ui.sidebar.agents]
row_gap = 0
rows = [
  ["state_icon", "workspace", "tab"],
  ["agent"],
]

[ui.sidebar.spaces]
row_gap = 0
rows = [
  ["state_icon", "workspace"],
  ["branch", "git_status"],
]
```

Agent rows accept these built-in tokens:

- `state_icon` — colored icon for the agent's semantic state.
- `state_text` — `idle`, `working`, `blocked`, `done`, or `unknown`, including a reported display label when present.
- `workspace` — workspace name.
- `tab` — tab name when available.
- `pane` — pane name when available.
- `agent` — detected or reported agent display name.
- `terminal_title` — latest OSC 0/2 terminal title after safety normalization.
- `terminal_title_stripped` — the terminal title with one recognized leading activity or spinner glyph and its following whitespace removed.
- `$name` — custom pane metadata named `name`.

Space rows accept these built-in tokens:

- `state_icon` — colored icon for the space's rolled-up agent state.
- `state_text` — text for the rolled-up agent state.
- `workspace` — workspace name.
- `branch` — Git branch when available.
- `git_status` — Git ahead and behind counts when nonzero.
- `$name` — custom workspace metadata named `name`.

Tokens render in their configured order. Herdr normally separates adjacent values with ` · ` and uses a single space after `state_icon`. Missing values and their separators disappear; a row disappears when none of its tokens have a value. Each layout may contain at most 16 rows, with at most 16 tokens in each row.

A token entry can also be an inline style table:

```toml
[ui.sidebar.agents]
rows = [
  ["state_icon", { token = "workspace", bold = false }, "tab"],
  [{ token = "$summary", fg = "#89b4fa", bold = true, dim = false }],
]
```

`fg` accepts strict `#RGB` or `#RRGGBB`. `bold` and `dim` accept booleans. Omitted fields preserve the token's contextual style; explicit `false` removes that modifier. Styling applies to one occurrence, so the same token may look different in another row or agent override. A foreground override replaces all semantic foregrounds inside that occurrence: for example, styled `git_status` ahead and behind counts use one color instead of their default green and red. Token styles never change separators or row backgrounds.

`row_gap` controls the blank terminal rows between entries, independently for the Agent and Space panels. It defaults to `0`, which packs entries together; set it to `1` to restore the previous spacing. It does not add spacing between the content lines declared in `rows`. Consecutive indented worktree children remain packed as one Space group.

Override the complete Agent layout for a known agent under `rows_by_agent`:

```toml
[ui.sidebar.agents]
rows = [
  ["state_icon", "agent", "state_text"],
  ["workspace", "tab"],
]

[ui.sidebar.agents.rows_by_agent]
claude = [
  ["state_icon", "agent", "state_text"],
  ["terminal_title_stripped"],
  ["workspace", "tab"],
]
```

An override replaces `rows`; it does not extend it. Override keys are case-sensitive canonical agent IDs such as `claude`, `codex`, and `pi`. Detection aliases such as `claude-code` are not accepted. Agents without an override, including custom reported agents, use `rows`.

Custom `$name` tokens are dynamic values, not literal text. Add the token to a layout, then report its value from a script or plugin:

```toml
[ui.sidebar.agents]
rows = [
  ["state_icon", "agent", "$model"],
  ["$summary"],
  ["workspace", "tab"],
]
```

```bash
herdr pane report-metadata <pane_id> \
  --source my-agent-hook \
  --token model=opus \
  --token summary="reviewing authentication"
```

Use `herdr workspace report-metadata` in the same way for custom Space tokens. Unreported custom tokens simply disappear.

Metadata reporters provide values only; styling stays in the local sidebar configuration. See [CLI reference: report metadata](/docs/cli-reference/#panes) for limits, clearing, sequencing, and expiry.

Sidebar row settings affect only the expanded desktop sidebar. Collapsed and mobile views keep their compact layouts.

## Edge bars

Each edge of the frame can carry a thin strip. All four are off by default, and each is configured on its own:

```toml
[shell.bars.top]
enabled = true
size    = 3      # rows for the top and bottom bars, columns for the left and right ones
border  = true   # a bordered bar needs size >= 3 to have room for its contents
```

Bars are bordered unless told otherwise, so a bar thinner than three asks for `border = false` — a one-row bordered bar has no room for a row of content between its two border lines.

A size outside 1–32, or a bordered bar too thin to hold a border and a row of content, is refused rather than adjusted: the bar is not drawn and the log names the edge. See `shell.bars` in the [Config reference](/docs/config-reference/) for colours and gradients.

### Dividing a bar into sections

A bar can be divided into at most eight parts along its long axis. Sections are written in the order they appear, and each one asks for its share in one of three ways:

```toml
[shell.bars.top]
enabled = true
size    = 3

[[shell.bars.top.sections]]
kind  = "fixed"
cells = 12        # exactly twelve cells, whatever else happens

[[shell.bars.top.sections]]
kind = "fill"     # share what is left; `weight` (default 1) sets the proportion

[[shell.bars.top.sections]]
kind   = "fill"
weight = 3

[[shell.bars.top.sections]]
kind = "content"
min  = 4
max  = 20         # at least four cells, at most twenty, as much as there is room for
```

Fixed sections are satisfied first, then content sections grow toward their maximum, and whatever remains is shared among the filling sections in proportion to their weights. A section that ends up with no cells is simply not drawn.

A bar carries eight sections unless it says otherwise. `max_sections` raises or lowers that, up to a hard ceiling of sixteen:

```toml
[shell.bars.top]
enabled      = true
size         = 1
border       = false
max_sections = 12
```

Writing more sections than the bar allows, asking for a `max_sections` of zero or more than sixteen, naming a `kind` Herdr does not know, or giving a content section a `max` below its `min` leaves that bar undivided rather than guessing: one unreadable section would otherwise renumber every section after it, and the number is how a section is addressed.

### Putting something in a section

A section is empty until it is given a widget. There are four kinds:

| `widget.kind` | Draws | Names |
|---|---|---|
| `label` | fixed text | `text` |
| `resource` | a machine counter, as a figure | `metric` |
| `meter` | the same counter, as a filled bar | `metric` |
| `icon` | one picture | `glyph`, or `art`, or `pixels` + `palette` |

No widget ever changes how wide its section is. The sizing rules above decide that, and content that does not fit is cut rather than pushing its neighbours around — clipping is by display width, so a two-cell emoji counts as two.

A `widget.kind` Herdr does not know, or `text` with no `widget.kind` to show it, leaves that section empty and is reported by `herdr config check`.

#### Text

```toml
[[shell.bars.top.sections]]
kind   = "fixed"
cells  = 10
widget = { kind = "label", text = "  CPU" }
```

#### A machine counter

`resource` writes the number; `meter` draws how full it is. Both name the same `metric`, and the value is sampled on the server's own clock rather than read by whatever draws it — so two sections showing the same metric always agree.

```toml
[[shell.bars.top.sections]]
kind   = "fixed"
cells  = 8
widget = { kind = "resource", metric = "cpu" }

[[shell.bars.top.sections]]
kind   = "fixed"
cells  = 10
widget = { kind = "meter", metric = "mem" }
```

`metric` is one of `cpu`, `mem` (`ram` is accepted as the same thing) or `swap`. A metric this build does not know is refused where it is written rather than drawn as an empty section: a typo that renders as blank cannot be told from a section left blank on purpose.

How often the machine is re-read is one setting for all of them:

```toml
[shell]
resource_interval_ms = 500   # default: 2000
```

Nothing is read at all unless a section asks for it, so a bar without a `resource` or `meter` costs nothing whatever this says.

Accepted between 250 and 60000. The floor is not a preference: a CPU percentage is the difference between two cumulative readings, and the kernel counts in jiffies — a hundred a second, so ten milliseconds each. At 250 ms a single-core machine has twenty-five of them to tell apart; at 100 ms it has ten, and the figure on screen starts reporting the counter's resolution rather than the machine's load. The ceiling is a typo guard — a reading once a minute describes history.

A value outside the range is reported by `herdr config check` and the default pace is kept. A bad number leaves you with a working meter and a sentence about the number, rather than a bar that quietly stopped.

#### A picture

An `icon` names its picture exactly one way. Writing two is refused rather than ranked, because a precedence rule between them is not something the config file can show:

```toml
[shell.bars.top]
enabled = true
size    = 3

# a grapheme the font already has
[[shell.bars.top.sections]]
kind   = "fixed"
cells  = 2
widget = { kind = "icon", glyph = "★" }

# a bundled picture, by name
[[shell.bars.top.sections]]
kind   = "fixed"
cells  = 10
widget = { kind = "icon", art = "herd" }

# a picture written here, in half blocks
[[shell.bars.top.sections]]
kind   = "fixed"
cells  = 10
widget = { kind = "icon", palette = { a = "mauve", b = "teal" }, pixels = [
  "..a....a..",
  "...a..a...",
  "....aa....",
  "....bb....",
  "...bbbb...",
  "..bb..bb..",
] }
```

Pixel art is drawn with the upper half block `▀`, which paints the foreground in the top half of a cell and the background in the bottom. One cell is therefore **two vertical pixels**, each with its own colour: a picture ten pixels wide by six tall occupies ten cells by three rows. Every character in `pixels` is a key into `palette`; `.` and a space are transparent and let the bar through. An odd number of pixel rows leaves the bottom half of the last cell row transparent rather than inventing a colour for it.

`palette` keys are single characters, and the values are written in the same grammar as `shell.bars.<edge>.color`. A key a row uses but the palette does not define is refused — writing `x` and believing it transparent looks exactly like writing `.`, and it is not.

Bundled `art` names available today:

| `art` | Size | What it is |
|---|---|---|
| `herd` | 10 × 6 pixels (10 cells × 3 rows) | Two chevrons narrowing into a stem — agents converging into one runtime |
| `dot` | 4 × 2 pixels (4 cells × 1 row) | A filled dot, for a bar one row tall |

A picture too wide or too tall for a section that declared its own `cells` is refused where it is written. A section sized by the terminal — `fill`, `content` — is not, because its width is not known until the terminal has one, and refusing then would mean a config that loads on one screen and not on another; there, a picture that does not fit is clipped like any other content.

#### Icons on a machine whose font may not have them

An `icon` widget can draw a single `glyph`. A glyph is only a picture where the font has that codepoint, and Herdr cannot ask a terminal whether it does — so on a machine without the font it renders as tofu, which reads as broken chrome rather than as a missing icon.

Give the section a `text` as well, and turn the switch off where the font is not there:

```toml
[shell]
glyph_icons = false          # default: true

[[shell.bars.top.sections]]
kind   = "fixed"
cells  = 6
widget = { kind = "icon", glyph = "\uf4bc", text = "cpu" }   # a Nerd Font codepoint
```

With the switch on, the glyph is drawn and the text is unused. With it off, the section draws the text instead, clipped by display width exactly as a label is.

The switch is deliberately a plain on/off rather than an `auto`: an `auto` would be pretending to detect something Herdr has no way to ask about.

Turning it off is the one setting that can invalidate a section that was valid before: a section with a glyph and no `text` — or a `text` of only spaces, which draws the same nothing — is reported by `herdr config check` rather than drawn empty, because an empty section is indistinguishable from one left empty on purpose.

Pictures made of cells are unaffected. `art` and `pixels` are drawn with half blocks, which every font has, so the switch leaves them alone.

### Making a section clickable

A section can carry an `action`. Without one it is an indicator: clicks land on it and stop there, but nothing happens.

```toml
[[shell.bars.top.sections]]
kind   = "fixed"
cells  = 12
action = { kind = "popup", argv = ["btop"] }
```

`popup` runs `argv` in a Herdr popup pane, the same pane a popup keybind opens — which means the popup takes the keyboard while it is up, and closing it gives the keyboard back.

The popup opens at half the terminal by default. `width` and `height` change that, spelled the same way as the popup size on a custom command keybind — a number of cells, or a percentage string:

```toml
[[shell.bars.top.sections]]
kind   = "fixed"
cells  = 12
action = { kind = "popup", argv = ["btop"], width = "80%", height = "70%" }
```

A size larger than the screen is brought back inside it. A terminal with no room for a popup at all refuses to open one rather than drawing a frame with nothing in it. A `width` or `height` on a section that opens no popup can never take effect, so `herdr config check` reports it rather than letting it sit there looking meaningful.

Only one popup can be open at a time. Clicking a section while one is already open opens nothing and closes nothing; Herdr says so instead, because dropping whatever is running in the popup is not something you can undo.

Clicking outside a popup sends Esc into the program rather than closing the pane, so an editor gets to save and quit on its own terms. Programs that do not read Esc that way — `btop` and `htop` quit on `q` — would leave the popup looking stuck, so clicking outside a second time closes it. Going back into the popup in between cancels that: Herdr reads it as "still using this", which matters when the Esc opened an unsaved-changes prompt.

A whole bar is chrome, so every click, release and scroll over one of its sections stops at the bar rather than reaching the pane behind it. A gesture that started somewhere else — a drag, a divider resize — keeps its owner even when the pointer crosses a bar.

An `action.kind` Herdr does not know, or a `popup` with no command in `argv`, leaves that one section without an action. Unlike a sizing mistake it does not undivide the bar, and it does not shift any other section's number. `herdr config check` names the edge, the section's index and what is wrong with it.

#### A second gesture on the same section

A `popup` section can answer the secondary press — right button, or a two-finger tap — differently from the primary one:

```toml
[[shell.bars.top.sections]]
kind   = "fixed"
cells  = 12
action = { kind = "popup", argv = ["btop"], secondary = "tab" }
```

`secondary = "tab"` opens the same command in a tab instead of a popup, for the times you want to keep it around. It is the only presentation there is today; anything else is refused rather than quietly treated as the default, because a misspelling that silently opens a popup is indistinguishable from not having written the key at all.

#### Running a plugin action

A section can invoke an installed plugin's action instead of a command line of its own:

```toml
[[shell.bars.top.sections]]
kind    = "fixed"
cells   = 8
widget  = { kind = "label", text = " review" }
action  = { kind = "plugin", command = "open" }
```

`command` here is the **plugin action's id**, not a shell command — the `id` of an entry in that plugin's `[[actions]]` table. Ids are made of letters, digits and `: . _ -`.

Herdr looks the id up across every installed plugin, so a bare id only works while it is unique. Ids are not: `open` is a common one, and several plugins can carry it at once. Where more than one matches, the press reports that the id is ambiguous rather than picking a plugin, so name the owner:

```toml
action = { kind = "plugin", command = "worktrunk.open" }
```

The qualified form is `<plugin id>.<action id>`. `herdr plugin action list` prints what is installed, with the `plugin_id` and `action_id` of each.

The plugin decides what the action does and how it is presented, so a plugin section carries none of the popup's own fields: `argv`, `width`, `height` and `secondary` are refused on a `plugin` action rather than ignored. Each would be a line that looks like it configures something and never can.

Pressing a section whose plugin is installed but switched off says so, which is a different message from a plugin that is not installed at all — the first is a setting, the second is an install.

#### Fields that can never take effect

Herdr refuses a half-finished edit rather than leaving it looking meaningful. A section with no `action.kind` but a leftover `width`, `height`, `secondary` or `command` is reported, because in every one of those shapes the command was removed and its settings stayed behind. The same rule catches a `command` on a `popup` action and an `argv` on a `plugin` one: both leave an id or a command line somewhere nothing will ever read it.

### What a section can be

A section is three independent choices, and every combination is allowed:

| How wide | What it shows | What a press does |
|---|---|---|
| `fixed` — exactly `cells` | nothing | nothing — an indicator that swallows the click |
| `fill` — a share of the rest, by `weight` | `label` | `popup` — run `argv` in a popup pane |
| `content` — between `min` and `max` | `resource` · `meter` | `plugin` — invoke an installed plugin's action |
| | `icon` | |

The three are asked separately on purpose: adding a widget never changes how wide a section is, and adding an action never changes what it draws. A picture that opens a popup is an icon widget plus a popup action, not a fourth kind of thing.

### Asking Herdr what a section can be

The table above is this page's copy of the grammar. Herdr will also tell you its own:

```bash
herdr shell spec           # the kinds, keys and a working example of each
herdr shell spec --json    # the same thing, for a program
```

It needs no server and no session, so it answers before anything is running. Every name it prints comes from the same table the parser dispatches on, and every example it prints is run through the real parser on each build — so an example it hands you is a config this build accepts, not one that used to work.

The JSON form is meant for agents writing config. Alongside each kind it carries the keys that kind reads and the keys it **refuses**, which is the half of a grammar you cannot otherwise learn without being turned down first:

```json
{ "kind": "plugin",
  "keys": ["command"],
  "refuses": ["argv", "width", "height", "secondary"],
  "example": "…" }
```

Metrics are listed twice on purpose: `names` is what to write, and `aliases` records that `ram` also works and means the same as `mem`.

### Recipes

Each of these is a complete fragment. After editing, `herdr config check` reports anything Herdr would refuse, and `herdr server reload-config` applies it without restarting panes.

**Show the machine's CPU on one side and memory on the other**

```toml
[shell.bars.top]
enabled = true
size    = 1
border  = false

[[shell.bars.top.sections]]
kind   = "fixed"
cells  = 8
widget = { kind = "resource", metric = "cpu" }

[[shell.bars.top.sections]]
kind = "fill"

[[shell.bars.top.sections]]
kind   = "fixed"
cells  = 10
widget = { kind = "meter", metric = "mem" }
```

The `fill` section in the middle carries nothing; it exists to push the two ends apart.

**Make a section a button**

```toml
[[shell.bars.top.sections]]
kind   = "fixed"
cells  = 12
widget = { kind = "label", text = " btop " }
action = { kind = "popup", argv = ["btop"], width = "80%", height = "70%" }
```

Any widget can carry any action, so the same works with an icon in place of the label.

**Put your own mark in the bar**

```toml
[shell.bars.top]
enabled = true
size    = 2
border  = false

[[shell.bars.top.sections]]
kind   = "fixed"
cells  = 4
widget = { kind = "icon", palette = { a = "accent" }, pixels = [
  ".aa.",
  "a..a",
  "a..a",
  ".aa.",
] }
```

Four pixel rows are two cell rows, which is why this bar asks for `size = 2`.

**Run a plugin action from the bar**

```toml
[[shell.bars.top.sections]]
kind   = "fixed"
cells  = 10
widget = { kind = "label", text = " palette " }
action = { kind = "plugin", command = "jt.command-palette.open" }
```

**Keep the bar readable where the font has no icon glyphs**

```toml
[shell]
glyph_icons = false

[[shell.bars.top.sections]]
kind   = "fixed"
cells  = 6
widget = { kind = "icon", glyph = "\uf4bc", text = "cpu" }
```

With the switch on the glyph is drawn, with it off the text is. Give every glyph section a `text` and one config works on both machines.

## Notifications

Herdr can notify you when a background agent finishes or needs input:

```toml
[ui.toast]
delivery = "herdr"
delay_seconds = 1

[ui.toast.herdr]
position = "bottom-right"
```

Choose `herdr` for an in-app toast, `terminal` for an outer-terminal notification that works well over SSH, `system` for the local OS notification service, or `off` to disable popups. Herdr suppresses popups for the active tab. Search `ui.toast` in the [Config reference](/docs/config-reference/) for positions, delay behavior, and clipboard feedback settings.

## Sound

Sound notifications play through the local Herdr client. Custom sounds must be mp3 files; relative paths are resolved from the config file's directory.

```toml
[ui.sound]
path = "sounds/notification.mp3"
done_path = "sounds/done.mp3"
request_path = "sounds/request.mp3"
```

`path` sets one sound for all sound notifications. `done_path` and `request_path` override only the finished and needs-input sounds.

Per-agent sound overrides accept `default`, `on`, or `off`. Use detected agent labels such as `claude`, `codex`, `devin`, or `droid` as keys. Droid is muted by default.

```toml
[ui.sound.agents]
droid = "off"
claude = "on"
```

## Advanced configuration

Search the [Config reference](/docs/config-reference/) for scrollback limits, nested launches, and other advanced or experimental settings. See [Session state and restore](/docs/session-state/) before enabling pane screen history; that guide explains the security trade-off of saving pane contents.

## Kitty graphics

Kitty graphics rendering for attached local clients is experimental and disabled by default:

```toml
[experimental]
kitty_graphics = true
```

Enable it only when testing terminal image behavior.

## Agent session restore

Herdr resumes supported Agent conversations after a server restart by default:

```toml
[session]
resume_agents_on_restore = true
```

Only panes with a valid native session reference from an official integration can resume; other panes restore as normal shells. See [Session state and restore](/docs/session-state/) for supported Agents and persistence behavior.

## IME cursor tracking

On macOS, AI Agent TUIs that hide the hardware cursor can prevent native input-method candidate windows from following the focused pane. Reveal a cursor anchor for those panes with:

```toml
[experimental]
reveal_hidden_cursor_for_cjk_ime = true
cjk_ime_agents = ["claude", "pi", "codex"]
```

Restricting `cjk_ime_agents` avoids showing an extra hardware cursor in unrelated applications. Search these keys in the [Config reference](/docs/config-reference/) for accepted Agent names and cursor shapes.

## Prefix input source switching

On macOS, Herdr can temporarily switch to the system ASCII-capable input source while prefix commands and prefix-launched modes are active:

```toml
[experimental]
switch_ascii_input_source_in_prefix = true
```

Herdr restores the previous input source when returning to terminal input or entering a text field. This setting has no effect on other platforms.
