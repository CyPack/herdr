# Stage · Side-by-side halves (fork behaviors)

The macro feature's first slice: two workspaces on one stage, each half under
its own strip — "iki ayrı terminal açmışız gibi". The POC is presentation
only: the LEFT half is the active workspace and keeps every input; the right
half paints and resizes but takes no clicks yet.

| id | behavior | why it matters | tests |
|---|---|---|---|
| TP-STAGE-SBS-01 | `enter_side_by_side(right)` pairs the ACTIVE workspace with `right` at a 50% split: compute carves strip and content into two rects with a one-column divider owned by neither; the left half keeps `view.pane_infos` (every existing consumer unchanged), the right half is computed through NEW named-workspace seams (`compute_pane_infos_for` / `compute_tab_surface_for` / `render_panes_for`) whose active-workspace wrappers keep old callers byte for byte; the right half's active tab is excluded from the full-size background sweep; pairing the active with itself is refused at the door, and a pairing that stopped making sense — right vanished, right == active, stage under 40 columns — heals whole on compute; the paint is real (divider column + the right half's own strip land in the buffer) | The user's ask is two worlds side by side with their own strips; a divider column owned by a pane would clip one world into the other; consumers re-checking validity each would drift — one heal site cannot; and the background sweep resizing the right half to full width every frame would make the split flicker between two sizes | `the_side_by_side_split_computes_two_disjoint_surfaces`, `an_invalid_pairing_heals_on_compute`, `the_stage_paints_the_divider_and_the_right_strip` |
| TP-SBS-FILES-01 | The right half can host the resident Files surface: two gestures summon it (the pane menu's `Open Files beside`, the dock Files entry's `Open in right split`), the stage stays on the terminal, every Files projection — geometry and hits alike — lives strictly inside the right rectangle, and being beside counts as being staged for bars, clicks and the resident generation. | The user asked for the file manager beside the focused terminal by exactly these two gestures; a Files that takes the whole screen is the thing this mode exists to avoid, and an on-screen surface that ignored clicks would be worse than none. | `files_beside_projects_the_file_manager_into_the_right_half`, `open_files_beside_gestures_summon_the_right_half`, `a_click_in_the_right_half_moves_the_files_cursor`, `a_missing_file_manager_heals_the_files_pairing` |
| TP-SBS-DRAG-01 | The one empty column the split already leaves between the halves is a grab handle: `compute_view` names it (`view.sbs_divider_rect`, gone when the stage is not split), a Down on it arms the SAME shared resize transaction the Miller and shell dividers use (`ResizeTargetId::SideBySide` — one capture owner, so a mid-drag pointer crossing a pane leaks nothing), Drag previews within the 20-80 band, and Up commits `ratio_percent` clamped to the same band. A press anywhere else arms nothing, and a released divider ignores stray drags. | The user asked for a flexible split ("resize edilemiyor" — the M7 architecture review queued this as the first step toward pane-hosted views); reusing the one transaction machine keeps the invariant that two captures cannot fight over the pointer, and the empty column already existed — no new pixel is drawn, the moving split is its own feedback. | `dragging_the_sbs_divider_commits_a_new_ratio`, `the_committed_ratio_never_leaves_the_band`, `an_sbs_drag_to_the_edge_clamps_the_ratio`, `a_press_off_the_divider_arms_no_sbs_drag`, `the_sbs_divider_rect_follows_the_ratio` |
| TP-SBS-FOCUS-01 | The split's keyboard follows the half the person last clicked: `SideBySideView.focus` starts Left (entering the split must not steal the keys from the pane), a press inside the Files half claims Right and the frozen input router then resolves `FocusedComponent` — the same Files key handler the full stage uses, proven end to end (the product byte road's Down arrow moves the Files cursor). A press back in the terminal half returns the keys. A trail-row click already moves the locations focus onto the trail through `focus_trail_row`'s own chain, so the arrows drive the rows the click chose. The focus dies with the split. | L4 — the user's queued ask: the beside surface could only be used by mouse. Mouse-first focus needs no new keybind and cannot collide with one; gating through the frozen router keeps the hidden-surface guarantee. | `clicking_a_half_moves_the_keyboard_with_it`, `a_click_in_the_right_half_moves_the_files_cursor` |
