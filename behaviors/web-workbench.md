# Web workbench — the browser pane's agent tie

The web workbench turns a browser pane into a reporting surface for one
agent conversation: what the human clicks, annotates, or captures in the
page lands in exactly that conversation. The tie must survive what a
terminal session goes through — splits, restores, agents closing —
without ever guessing.

| id | behavior | why it must not be lost | tests |
|---|---|---|---|
| TP-WEB-LINK-01 | A web pane carries a `WebLink`: the linked agent pane's public number, the agent conversation's session identity, the url, and a state. The session outranks the number everywhere — a restore or a rearranged layout can hand a number to someone else, but a session id names one conversation only. `pane.web.open` resolves the tie in strict order: explicit `agent` (public pane id or agent name, agents only), else the target pane's own agent, else the tab's only agent. Capture writes the link into the pane snapshot as-is; restore re-stamps it against the agents that actually came back: session match → `linked` with the number corrected to the session's new seat, number-only match with an agent seated there → `stale`, neither → `orphan`. The API reports the tie on every web pane as `PaneInfo.web`. | Without a red test the next merge can silently unlink every web pane a restore touches, or hand its reports to whichever agent inherited a pane number — the workbench's one promise, "this page reports to that conversation", dies invisibly. | `a_web_pane_snapshot_carries_its_agent_link`, `a_restored_link_follows_the_session_over_the_number`, `a_restored_link_without_its_session_goes_stale_on_the_number`, `pane_web_open_links_the_target_agent_pane`, `pane_web_open_links_the_named_agent`, `pane_web_open_adopts_the_tabs_only_agent`, `two_web_panes_keep_their_own_agents_apart` |
| TP-WEB-LINK-02 | The tie is deliberate or it does not exist. Beside a plain shell with no agent in the tab the pane opens `unlinked` — a guessed tie would carry a human's annotations into the wrong conversation, worse than no tie at all. When the linked agent conversation closes, its web panes go `orphan` rather than quietly keeping a dead address. A snapshot from before the field reads back clean: the link is additive, never a migration. | A wrong-guess regression or a dead tie stays invisible until a human's report lands in a stranger's conversation. | `pane_web_open_stays_unlinked_beside_a_plain_shell`, `an_agents_close_orphans_its_web_panes`, `a_restored_link_with_no_home_is_orphaned`, `an_old_pane_snapshot_without_a_web_link_still_reads` |
