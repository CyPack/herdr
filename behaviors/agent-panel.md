# Agent panel — active-row highlight and the close road

The lower sidebar panel answers "which agent am I on" at a glance. The active
row speaks the active tab's visual language — accent background with contrast
text — so the same question reads the same way on both surfaces, and the
passive rows give up their bold so the eye lands on the active one. Chosen by
the user on 2026-07-29 (accent-row model + passive dimming); design rationale:
`.local/prd/2026-07-29-flash-and-agent-panel-PRD.md`.

| TP-AGPANEL-02 | A passive agent's name is drawn without bold | Every row shouts at the same volume, so the active card's emphasis carries no information | `the_active_agent_row_wears_the_accent_background_and_the_rest_stay_muted` |

| TP-AGPANEL-04 | "Close agent" closes the row's OWN pane through the pane close road (graceful close with its confirmation gate intact, never a kill), not whichever pane is focused | Closing from the panel kills the wrong agent — the focused one — or bypasses the worktree-group confirmation the pane road owns | `closing_an_agent_row_closes_that_row_pane_not_the_focused_one` |

| TP-AGPANEL-08 | Closing an agent that is already remembered refreshes its row (newest position, dormant again) instead of adding a twin | Two ghosts with one identity leave the user guessing which of them revives — and the answer is neither, reliably | `closing_the_same_agent_again_refreshes_the_row_instead_of_duplicating` |
| TP-AGPANEL-09 | The ledger is a fixed-capacity ring (8); the oldest row is evicted | Closing agents is a daily gesture by the hundreds; an unbounded list is unbounded memory wearing a feature's name | `the_ledger_evicts_its_oldest_beyond_capacity` |

| TP-AGPANEL-11 | A landed revival leaves the graveyard; a failed one returns to rest, clickable again | A row bricked in `Reviving` by one failure is inert to every later click for no reason the user can see | `a_finished_revival_leaves_and_a_failed_one_rests_again` |
| TP-AGPANEL-12 | The pane-close API road births the ghost BEFORE removal, while the terminal, the tab and the resume key are all still alive | Deriving the record afterwards is how #46 ended up spawning in `$HOME` — the state it needs is gone | `closing_an_agent_pane_leaves_a_ghost_in_the_ledger` |
| TP-AGPANEL-13 | A plain shell pane leaves no ghost | A graveyard of every closed shell buries the agents it exists to remember | `closing_a_plain_shell_pane_leaves_no_ghost` |
| TP-AGPANEL-14 | An agent whose process exits by itself becomes a ghost too (the `agent_released` road) | Only user-closed agents would be remembered; a crashed agent vanishes silently and the user asks where it went | `an_agent_that_exits_by_itself_becomes_a_ghost` |
| TP-AGPANEL-15 | The session snapshot carries the closed agents, newest first, with each row's in-flight revival state | The graveyard would be a TUI ornament; the PWA and every other client would see a different truth | `the_session_snapshot_carries_closed_agents_newest_first` |
| TP-AGPANEL-16 | An empty graveyard leaves no trace on the wire (`default` + skip-if-empty) | Old clients choke on new servers, or the field's absence reads as an error | `an_empty_graveyard_is_absent_from_the_snapshot_wire` |
| TP-AGPANEL-17 | The resume recipe is frozen at close time; the terminal's own reported session outranks the session the tab was born resuming | The report tracks compacts and forks, the birth id does not; and at revival time both are gone (#46's class) | `the_harvest_freezes_the_terminals_own_session_recipe` |
| TP-AGPANEL-18 | A revival that cannot answer for its directory (none recorded, or gone from disk) is refused with a reason and the row stays dormant | Guessing lands in `$HOME` — the exact #46 failure; and a refusal that flips state bricks the row | `a_revival_without_a_livable_directory_is_refused_and_stays_clickable` |
| TP-AGPANEL-19 | A ghost without a session recipe is refused with a reason instead of launching a stranger | A fresh agent wearing the old name is not a revival; the user loses the conversation and trusts the panel less | `a_revival_without_a_session_recipe_is_refused` |
| TP-AGPANEL-20 | A ghost whose conversation already lives in a wired tab focuses that tab and leaves the graveyard — no twin | #45's lesson wearing grey: one session, one surface. | TP-AGPANEL-21 | A revival launches along its own agent's existing road — claude with the chat drawer's exact launch, others with the restore road's plan | A third argv invented for revival drifts from the other two the next time either changes | `a_revival_launch_matches_the_agents_existing_road` |
| TP-AGPANEL-22 | The graveyard renders after the living rows: a separator, then plain-text ghost rows that dim AND lean (italic); a reviving row wears a static ellipsis | Dim alone collides with the passive agent token, which already dims — the third class stops reading as a class; an animated ghost would need a ticking backend (R6's line) | `closed_agents_render_dimmed_under_a_separator` |
| TP-AGPANEL-23 | The ghost click resolves through the painter's own layout function (`closed_agent_row_slots`); the separator and off-rows name nobody | A hit box beside its paint: clicks revive the wrong ghost or dead furniture becomes a button | `a_click_on_a_ghost_row_names_that_ghost` |
| TP-AGPANEL-24 | Revival is a protocol method (`closed_agent.revive`); refusals answer with a stable code and readable reason | A private TUI gesture leaves the PWA a second-class client, and a refusal nobody can read is a silent bug | `revival_travels_the_api_road_with_visible_refusals` |
| TP-AGPANEL-25 | The tab-close road births ghosts for its agent panes before the cascade removes them; a refused close (the last tab) births nothing | An agent closed by its tab vanishes without a ghost — or worse, a refused close leaves a living agent haunting the list | `closing_a_tab_leaves_its_agent_in_the_ledger` |
| TP-AGPANEL-26 | The grey row wears the tab's own name when it has one; the agent kind is only the fallback | Three claude ghosts in one list are indistinguishable — the row answers "an agent closed", never "which one" | `a_ghost_wears_the_tabs_own_name_when_it_has_one` |
| TP-AGPANEL-27 | The workspace card's "+" menu answers on the production road: an agent starts a chat in that workspace's own checkout, and the worktree verbs queue their requests. | The arm lived only in the `#[cfg(test)]` sibling of `apply_context_menu_action`, so every test passed while the menu opened, offered its agents, and started nothing — the affordance was dead in the product and no test could see it. This is the second instance of that shape in this tree (TP-DAILY-11 was the first), which is why the rule is now to grep BOTH bodies for every `ContextMenuKind` rather than to trust the one the tests reach. | `the_workspace_plus_menu_starts_a_chat_on_the_production_road` |
| TP-AGPANEL-28 | An agents-panel row offers "Move to..." **only when** the ledger knows which chat it is running (`Tab::resumed_session_id`), the identity is read when the menu OPENS, and the verb opens the same target picker the chat row opens — on both the test and the production body. | This is the surface where running agents actually are, and "send this one somewhere" is the request that started the feature. But the identity exists only for a tab opened to resume a known session; a freshly started chat has none yet, and offering a move that cannot be honoured is worse than offering nothing. Reading the identity when the verb fires instead of when the menu opens repeats TP-AGPANEL-06's failure: a menu outlives the panel it was opened from and a late lookup answers for whatever moved into that slot. Adding the item without adding the production arm ships a dead affordance — #91 was exactly that, in exactly that body. | `an_agent_row_with_a_known_chat_offers_to_move_it`, `the_agent_row_menu_offers_exactly_the_close_verb`, `moving_from_an_agent_row_opens_the_picker_on_the_production_road` |
| TP-AGPANEL-29 | When a graveyard exists, the panel's scroll ceiling reserves the last two rows for it (separator + one ghost); with no ghosts the ceiling is unchanged. | The ceiling used to be computed from the living rows alone and the graveyard was painted only into whatever space they left over. On a panel that is always full — fifty-nine panes were measured on the machine this was reported from — those two rules meet badly: leftover space never appears, and NO scroll position reaches the ghosts. The section was unreachable, which is indistinguishable from absent, and that is how it was reported. Reserving unconditionally would be the opposite error: an empty graveyard would open a gap under the panel that promises more below and delivers nothing. One row is never enough either — a separator with nothing under it is the rendering bug the graveyard contract already forbids. | `a_full_panel_can_still_be_scrolled_down_to_its_graveyard`, `with_no_ghosts_the_panel_ceiling_is_unchanged`, `a_short_panel_still_shows_its_graveyard_without_scrolling` |
